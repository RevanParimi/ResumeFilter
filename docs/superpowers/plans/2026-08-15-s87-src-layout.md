# S8.7 src layout — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `app/` to `src/app/` with zero behaviour change, so
`/code-review ultra src/` scopes to the core code instead of drowning in docs prose.

**Architecture:** A pure `git mv` in its own commit (red by construction),
followed by one commit fixing the nine references the move invalidates, plus a
derived guard that fails if `app` ever resolves from outside `src/`. The package
keeps the name `app`, so all 1,489 import statements are untouched. The
container mirrors the repo layout exactly, so one `parents[N]` arithmetic is
valid in both places.

**Tech Stack:** Python 3.11/3.12, hatchling, pytest, FastAPI/uvicorn, Alembic,
Docker.

**Spec:** `docs/superpowers/specs/2026-08-15-s87-src-layout-design.md`

## Global Constraints

- **Pure move.** The package keeps the name `app`. Do NOT rename to `veritas` —
  decided against by the user 2026-08-15 (spec §2.1).
- **Zero logic edits in the same commit as a move.** Task 2 is `git mv` only.
- **No behaviour change anywhere.** If a change alters what the app does, it is
  out of scope and belongs in a different sprint.
- `pytest -q` must be green before merge (it constrains merges, not
  intermediate commits — Task 2 is red on purpose).
- Only `app/` moves. `tests/`, `scripts/`, `alembic/`, `frontend/`,
  `config.yaml`, `alembic.ini`, `Dockerfile` all stay at the repo root.
- Commit messages: no `Co-Authored-By` trailer.
- Nothing in this sprint creates a cloud resource or pushes to a remote.

### Task 1: The guard, red on today's layout

**Files:**
- Create: `tests/test_src_layout.py`

**Interfaces:**
- Consumes: nothing.
- Produces: nothing importable. This is a leaf test.

- [ ] **Step 1: Write the failing test**

```python
"""`app` must resolve from `src/`, and from nowhere else.

This sprint moves the package. Three ways that fails SILENTLY, all of which
leave a green suite:

1. A STALE EDITABLE INSTALL. The venv at `.resume/` holds
   `_editable_impl_depth_eval_engine.pth`, generated at install time against
   the OLD layout. Until `pip install -e .` is re-run it can resolve `app` to
   a path the tree no longer has.
2. A MISSING PYTHONPATH in some context nobody checked -- the ~20 smoke
   scripts launch `python -m uvicorn app.main:app` as SUBPROCESSES with
   `cwd=ROOT`, so pytest's `pythonpath` never reaches them.
3. A LEFTOVER `app/` AT THE REPOSITORY ROOT -- the worst outcome of a
   half-completed `git mv`, because every import resolves to it quietly and
   the whole suite passes against code that is no longer the code.

Derived from the live module object rather than a hand-maintained list, which
is the shape this repo has had to learn five times.
"""

from __future__ import annotations

from pathlib import Path

import app

ROOT = Path(__file__).resolve().parents[1]


def test_the_package_resolves_from_src():
    resolved = Path(app.__file__).resolve()
    assert resolved.parents[1] == ROOT / "src", (
        f"`import app` resolved to {resolved} -- expected it under "
        f"{ROOT / 'src'}. A stale editable install, a missing PYTHONPATH, or "
        f"a leftover app/ at the repo root would all look like this."
    )


def test_no_package_directory_survives_at_the_repo_root():
    """The half-completed move. `import app` above could still be correct
    while a partial copy sits at the root shadowing nothing yet."""
    assert not (ROOT / "app").exists(), (
        "app/ still exists at the repository root after the move to src/app/"
    )
```

- [ ] **Step 2: Run it to verify it fails**

Run: `python -m pytest tests/test_src_layout.py -v`

Expected: BOTH tests FAIL. `test_the_package_resolves_from_src` fails because
`app.__file__` resolves to `<repo>/app/__init__.py`, whose `parents[1]` is
`<repo>`, not `<repo>/src`. `test_no_package_directory_survives_at_the_repo_root`
fails because `app/` is still there.

This red is the point of the task — do not proceed until you have SEEN both
fail with those messages.

- [ ] **Step 3: Commit the red test**

```bash
git add tests/test_src_layout.py
git commit -m "test(s87): the src-layout guard, red before the move

Three silent failures this catches, all of which leave a GREEN suite: a stale
editable install still pointing at the old path, a missing PYTHONPATH in one
of the ~20 smoke subprocesses, and a leftover app/ at the repo root that
imports resolve to quietly.

Red on purpose. Task 2 moves the package; Task 3 makes this green."
```

### Task 3: The nine references the move invalidated

**Files:**
- Modify: `pyproject.toml:44` and `[tool.pytest.ini_options]`
- Modify: `Dockerfile` (the `COPY app` line; add `ENV PYTHONPATH`)

- Modify: `tests/test_metrics.py:125`

**Interfaces:**
- Consumes: the package at `src/app/` from Task 2.
- Produces: a green tree. `import app` resolves via `pythonpath = [".", "src"]`
  under pytest, via the editable install for subprocesses, and via
  `PYTHONPATH=/srv/app/src` in the container.

- [ ] **Step 1: `pyproject.toml` — the build target and the test path**

In `[tool.hatch.build.targets.wheel]`:

```toml
packages = ["src/app"]
```

In `[tool.pytest.ini_options]`:

```toml
pythonpath = [".", "src"]
```

The `"."` STAYS and is load-bearing: `tests/test_report_data_migration.py:16`
does `from scripts.migrate_reports_into_main_db import migrate`. Dropping it
breaks that import.

- [ ] **Step 2: Refresh the editable install**

```bash
python -m pip install -e . --no-deps
```

`--no-deps` because `requirements.txt` already installed everything and this
machine is slow; the point is only to regenerate
`_editable_impl_depth_eval_engine.pth` against the new layout.

Verify it took:

```bash
python -c "import app, pathlib; print(pathlib.Path(app.__file__).resolve())"
```

Expected: a path containing `src\app\__init__.py` (or `src/app/__init__.py`).
If it still prints the old location, the install did not refresh — do not
continue, the ~20 smoke scripts in Task 5 depend entirely on this.

- [ ] **Step 3: The two depth expressions inside the package**

`src/app/core/migrate.py:29` — the file is now one level deeper:

```python
ROOT = Path(__file__).resolve().parents[3]
```

`src/app/main.py:249`:

```python
    _ui_dir = Path(__file__).resolve().parents[2] / "frontend"
```

Check the arithmetic by hand both ways before moving on:
- repo: `<repo>/src/app/core/migrate.py` → `[0]=core [1]=app [2]=src [3]=<repo>` ✓
- image: `/srv/app/src/app/core/migrate.py` → `[3]=/srv/app` ✓ (where `alembic.ini` is)
- repo: `<repo>/src/app/main.py` → `[0]=app [1]=src [2]=<repo>` ✓
- image: `/srv/app/src/app/main.py` → `[2]=/srv/app` ✓ (where `frontend/` is)

**`main.py`'s is the dangerous one.** It is guarded by `if _ui_dir.is_dir():`,
so a wrong depth does not raise — it silently skips the mount and every UI page
404s. `tests/test_ui_mount.py` is what catches it.

- [ ] **Step 4: The Dockerfile — mirror the repo, do NOT flatten**

Change the COPY line:

```dockerfile
COPY src/app ./src/app
```

And add, near the other ENV lines at the top:

```dockerfile
# S8.7: the package lives at src/app/ and the image MIRRORS that layout rather
# than flattening it to ./app. Flattening would leave migrate.py's parents[3]
# pointing at /srv instead of /srv/app -- alembic.ini not found, at RUNTIME,
# after the container has already reported itself started. Same failure class
# as S8.6's missing frontend/. One depth arithmetic, valid in both places.
ENV PYTHONPATH=/srv/app/src
```

`CMD ["uvicorn", "app.main:app", ...]` stays byte-identical, and so does
`railway.json`'s `startCommand`.

- [ ] **Step 5: `tests/test_image_contents.py` — the floor**

Line 38:

```python
FLOOR = {"src/app", "config.yaml", "alembic.ini"}
```

`_copied_sources()` strips a leading `./` and a trailing `/` only, so
`COPY src/app ./src/app` normalises to exactly `src/app`. No parser change
needed.

- [ ] **Step 6: `tests/test_model_registration.py` — the glob AND the dotted name**

Two edits in `_modules_on_disk()`, and the second is easy to miss:

```python
def _modules_on_disk() -> set[str]:
    """Every `src/app/**/models.py` that actually declares a table."""
    out: set[str] = set()
    src = ROOT / "src"
    for path in (src / "app").rglob("models.py"):
        text = path.read_text(encoding="utf-8")
        if "__tablename__" not in text:
            continue
        rel = path.relative_to(src).with_suffix("")
        out.add(".".join(rel.parts))
    return out
```

The `relative_to(src)` is the one that matters. Left as `relative_to(ROOT)` it
produces `src.app.rights.models`, which matches nothing in either import list,
so **all** modules read as missing and both drift tests fail with a confusing
message. `test_the_scan_finds_something` asserts `app.candidates.models` is in
the result, so a mistake here fails loudly rather than vacuously.

- [ ] **Step 7: `tests/test_deploy_doc.py` — the boot.py source read**

Line 64:

```python
    source = (ROOT / "src" / "app" / "core" / "boot.py").read_text(encoding="utf-8")
```

- [ ] **Step 8: `tests/test_metrics.py` — the metric-name scan**

Line 125:

```python
    root = Path(__file__).resolve().parent.parent / "src" / "app"
```

This one is **absent from the roadmap's touchpoint list**; it was found by
scanning for `__file__` rather than by reading the roadmap. Left alone, `root`
points at a directory that no longer exists, `rglob` yields nothing, and the
test passes **vacuously** — it would stop checking metric names entirely
without ever going red.

- [ ] **Step 9: Run the guard from Task 1**

Run: `python -m pytest tests/test_src_layout.py -v`

Expected: both tests PASS.

- [ ] **Step 10: Run the full suite**

Run: `python -m pytest -q 2>&1 | tail -5`

Expected: the Task 2 Step 1 baseline **+ 2** (the two guard tests), zero
failures. A count that is lower means a test file stopped being collected —

- [ ] **Step 11: Commit**

```bash
git add -A
git commit -m "fix(s87): the nine references the move invalidated

Two depth expressions inside the package (migrate.py parents[2]->[3],
main.py parents[1]->[2]), the build target and pytest pythonpath, the

THE DOCKERFILE MIRRORS THE REPO RATHER THAN FLATTENING. \`COPY src/app ./app\`
```
